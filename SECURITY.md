# Security Policy

Thank you for helping keep PhpSPA and its users safe.

## Reporting a vulnerability

Please **do not open a public GitHub issue** for a suspected security vulnerability.

Use one of these private reporting channels instead:

1. **Preferred:** [Open a private GitHub security advisory](https://github.com/dconco/phpspa/security/advisories/new).
2. If private reporting is unavailable, email [dconco@spyrochat.org](mailto:dconco@spyrochat.org) with the subject `PhpSPA security report`.

Include as much of the following as possible:

- The affected PhpSPA version, branch, component, and configuration.
- A clear description of the vulnerability and its potential impact.
- Reproduction steps or a minimal proof of concept.
- Relevant request data, logs, stack traces, or screenshots with secrets and personal data removed.
- Any suggested remediation and your preferred disclosure timeline.
- Whether you would like to be credited in the advisory.

Do not send credentials, access tokens, private user data, or destructive payloads. If sensitive files are needed to reproduce the issue, describe them first so we can arrange an appropriate transfer method.

## What to expect

We aim to acknowledge a report within three business days. We will investigate it, keep the reporter informed of material progress, and coordinate a fix and disclosure when the issue is confirmed. Please allow reasonable time for remediation before publishing details.

## Supported versions

Security fixes are normally applied to the latest released version and the actively maintained development branch. Users may be asked to upgrade when a fix cannot safely be backported.

## Good-faith research

We welcome research performed in good faith. Please:

- Test only against systems and data you own or are authorized to access.
- Minimize access to data and stop testing once a vulnerability is demonstrated.
- Avoid service disruption, persistence, social engineering, and destructive actions.
- Report the issue privately and give us a reasonable opportunity to remediate it.

We will not pursue action against researchers who follow this policy and make a good-faith effort to avoid harm and privacy violations.
